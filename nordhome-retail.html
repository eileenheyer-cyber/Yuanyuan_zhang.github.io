NordHome Retail Analytics

End-to-end project: data warehouse built on Kimball, ETL in PostgreSQL and a Power BI report for the H1 2024 review.

Role

End-to-end: data modeling, ETL, BI

Timeframe

Jan 2021 – Jun 2024 (data), 2026 (build)

Dataset

166,000+ rows, 7 CSV sources

Technology

PostgreSQL, SQL, Python, Power BI, DAX

Starting point

A fictional e-commerce retailer with markets across DACH, the Nordics and Benelux. I generated the dataset myself: seven CSV sources with over 166,000 rows and deliberately built-in data quality issues across six categories — from missing customer IDs to contradictory order statuses.

What I built

  • Layered architecture raw → stg → mart in plain SQL
  • Star schema with conformed dimensions (dim_customer, dim_date) and four fact tables
  • Handling orphaned records via -1 placeholders (unknown member) and a lightweight audit log
  • SCD type 2, surrogate keys, window functions
  • Fixed a revenue double-counting bug through correct grain definition

Power BI report

Executive Overview with KPI cards (net revenue, net AOV, gross margin, completed orders, return rate), a revenue trend with H2 estimate, and a "Revenue at risk" panel: 18.0% of net revenue is lost to cancellations, returns and refunds.

Technology

PostgreSQL SQL Python Power BI DAX Deneb
