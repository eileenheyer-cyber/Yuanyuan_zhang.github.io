Regression analysis

Generalized Linear Models

Linear regression predicts continuous outcomes, such as sales revenue. But how do we predict whether a customer will churn, or how many orders a store will receive? Generalized Linear Models (GLMs) extend the same basic framework to these different outcomes. By choosing an appropriate probability distribution and link function, we can model continuous values, probabilities or counts within one framework. This post builds on the distributions from Four Common Discrete Distributions and Normal Distribution, and shows how they plug into a regression model.

The problem: linear regression does not fit every outcome

Ordinary linear regression works well when the outcome is a continuous number, such as revenue or temperature. Ordinary linear regression models the conditional mean of an outcome as a linear combination of predictors. Under the classical assumptions, the errors have constant variance and are independent; normality is mainly relevant for exact small-sample statistical inference.

Many business questions break these assumptions:

  • Will this customer churn? The outcome is yes or no. A straight line can predict 1.3 or −0.2, which are not valid probabilities.
  • How many orders will we get tomorrow? The outcome is a count: 0, 1, 2 and so on. It can never be negative, and the spread grows as the average grows.

You can force a straight line through such data, but you will get impossible predictions and misleading error estimates. We need a model that respects the nature of the outcome.

The big idea: three components

A generalized linear model (GLM) keeps the part of linear regression that works, a weighted sum of predictors, and makes the rest flexible. Every GLM is built from three components:

  • Random component. The distribution of the outcome Y: normal, binomial or Poisson.
  • Systematic component. The linear predictor η = β₀ + β₁X₁ + … + βₚXₚ, the same weighted sum you know from linear regression.
  • Link function g. It connects the two by transforming the expected outcome so that it can be written as the linear predictor.

g( E[Y | X] ) = β₀ + β₁X₁ + … + βₚXₚE[Y | X] is the expected outcome given the predictors, g is the link function and the right side is the linear predictor η.

The link function maps the expected outcome onto the scale of the linear predictor. This allows the model to use a linear combination of predictors while respecting the constraints imposed by the chosen outcome distribution. A GLM is fitted by maximum likelihood. For the normal case this gives the same result as ordinary least squares.

Three examples

Continuous, binary and count outcomes each call for a different distribution and link function. The inverse of the link function turns the linear predictor η back into the expected outcome.

ModelLink functionExpected outcome
Linear regressionIdentityμ = η
Logistic regressionLogitp = 1 / (1 + e−η)
Poisson regressionLogμ = eη

Linear regression: identity link

The identity link changes nothing: the prediction is the linear predictor itself. A one-unit increase in X changes the predicted conditional mean by β, holding the other predictors constant. If the outcome is order value, β is a change in euros.

Logistic regression: logit link

For a yes/no outcome, the model works with the odds of the event, p / (1 − p), and takes the logarithm. Solving for p always gives a value between 0 and 1.

log( p / (1 − p) ) = η, so p = 1 / (1 + e−η)p is the probability of the event, for example that a customer churns.

Raising e to the power of a coefficient gives an odds ratio: eβ is the multiplicative change in the odds associated with a one-unit increase in X, holding the other predictors constant.

Poisson regression: log link

For counts, the model takes the logarithm of the expected count. Reversing it gives μ = eη, which is always above zero. Raising e to the power of a coefficient gives a multiplicative effect on the expected count: eβ is the factor by which the expected count changes with a one-unit increase in X, holding the other predictors constant. A factor of 1.10 means 10% more events.

Watch the spread of the counts

Poisson regression assumes that the variance of the counts is about equal to their mean. If your counts vary much more than that, the model understates the uncertainty, and a negative binomial model is a common alternative. If the counts cover different exposure periods, such as stores that are open for different numbers of days, the model also needs an offset for the exposure.

Comparing the link functions

The linear predictor is the same in all three models. What changes is how it is translated into a valid prediction.

Business application

Imagine a retailer with customer and order data. One framework covers three typical questions:

  • Predict sales (linear). What is the expected order value, given customer segment, discount and season? Each coefficient is an effect in euros.
  • Predict customer churn (logistic). Which customers are likely to stop buying, based on days since the last order, order frequency and support contacts? Each coefficient is an odds ratio.
  • Predict order counts (Poisson). How many orders will arrive per day, given weekday, promotion and weather? Each coefficient is a multiplicative effect on the expected count, which helps with staffing and stock.

In Python, statsmodels fits all three models with the same function. You only change the formula and the distribution family; the usual link function is set automatically for each family.

import numpy as np
import statsmodels.api as sm
import statsmodels.formula.api as smf

# 1. Order value (continuous): Gaussian family, identity link
sales_model = smf.glm("sales ~ discount + C(season)", data=df,
                      family=sm.families.Gaussian()).fit()

# 2. Churn (0/1): Binomial family, logit link
churn_model = smf.glm("churned ~ recency + frequency + support_tickets", data=df,
                      family=sm.families.Binomial()).fit()

# 3. Daily orders (count): Poisson family, log link
orders_model = smf.glm("orders ~ C(weekday) + promo_active", data=df,
                       family=sm.families.Poisson()).fit()

# Logistic regression: odds ratios
odds_ratios = np.exp(churn_model.params)

# Poisson regression: multiplicative effects on the expected count
count_effects = np.exp(orders_model.params)

print(odds_ratios)
print(count_effects)

A Gaussian GLM with an identity link gives the same result as ordinary least squares under the usual setup, but you do not need a GLM for ordinary linear regression. It is shown here only to make the three models comparable.

Reading the exponentiated coefficients

Exponentiated coefficients are interpreted relative to the model's link function. For logistic regression they are odds ratios. For a standard log-link Poisson model they are multiplicative effects on the expected count. They are not automatically causal effects.

How to explain it to stakeholders

“Our churn model looks at how many support tickets a customer opened in the last 90 days. Each extra ticket multiplies the customer's odds of leaving by 1.5. A customer who starts at a 20% churn risk moves to about 27% after one extra ticket.”

“For order volume, we model daily orders as counts. A promotion day multiplies the expected number of orders by about 1.2, so if we normally get 150 orders a day, we should plan for roughly 180 on a promotion day.”

“So the business question is: which customers should the service team contact first, and how much staff and stock do we need on promotion days?”

Key takeaway

Linear, logistic and Poisson regression are one mathematical framework, adapted to different outcome distributions through the choice of distribution and link function. Before you fit a model, ask what kind of outcome you are predicting: a continuous number, a yes/no, or a count. That answer tells you which GLM to use.
