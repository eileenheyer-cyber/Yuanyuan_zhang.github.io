One-Hot Encoding: How to Make Categories Readable for Machine Learning

Most machine learning models only understand numbers. But real business data is full of text: product categories, regions, payment methods, customer segments.

Before a model can use any of this, the text has to be converted into numbers. How you do that matters more than most beginners expect. One-hot encoding is the most common way to do it, and it is one of those techniques that looks trivial until it quietly breaks your model.

The problem: categories are not numbers

Imagine a small retail dataset:

order_idcategoryrevenue
1Furniture240
2Lighting85
3Textiles60
4Furniture310

The obvious quick fix is to give every category a number:

  • Furniture = 1
  • Lighting = 2
  • Textiles = 3

This is called label encoding, and it has a hidden problem. The numbers imply an order and a distance: Textiles (3) looks "bigger" than Furniture (1), and the gap between Furniture and Lighting looks the same as between Lighting and Textiles. A linear model or a distance-based model will treat this as real information. But "Lighting" is not twice "Furniture". The categories have no natural order.

The idea: one column per category

One-hot encoding avoids this by creating a separate yes/no column for every category:

order_idcategory_Furniturecategory_Lightingcategory_Textilesrevenue
1100240
201085
300160
4100310

Each row has exactly one "hot" (1) value and the rest are 0, hence the name. No category is bigger than another. They are simply different.

How to do it in Python

Option 1: pandas (quick and good for exploration)

import pandas as pd

df = pd.DataFrame({
    "order_id": [1, 2, 3, 4],
    "category": ["Furniture", "Lighting", "Textiles", "Furniture"],
    "revenue": [240, 85, 60, 310],
})

df_encoded = pd.get_dummies(df, columns=["category"], dtype=int)
print(df_encoded)

Option 2: scikit-learn (better for real ML pipelines)

from sklearn.preprocessing import OneHotEncoder

encoder = OneHotEncoder(handle_unknown="ignore", sparse_output=False)
encoded = encoder.fit_transform(df[["category"]])

print(encoder.get_feature_names_out())
# ['category_Furniture' 'category_Lighting' 'category_Textiles']

Why prefer scikit-learn for modeling? The encoder remembers which categories it saw during training. When new data arrives with a category the model has never seen, handle_unknown="ignore" encodes it as all zeros instead of crashing. With pd.get_dummies, train and test data can end up with different columns, which is a classic source of confusing errors.

Three things that can go wrong

  • The dummy variable trap. If you have three categories, two columns are enough: when both are 0, it must be the third. Keeping all three makes the columns perfectly correlated, which can cause problems for linear and logistic regression. Fix it with drop_first=True in pandas or drop="first" in scikit-learn. Tree-based models don't care much.
  • High cardinality. A column like postal_code or product_id can have thousands of unique values. One-hot encoding turns that into thousands of columns, most of them zeros. This is slow, memory-hungry and can lead to overfitting. In that case, consider grouping rare categories into "Other", frequency encoding, or target encoding.
  • Encoding before splitting your data. Fit the encoder on the training set only, then apply it to the test set. Fitting on the full dataset leaks information about the test data into your preparation step.

When should you use it?

SituationRecommendation
Categories with no natural order (region, color, payment method)One-hot encoding
Categories with a real order (small < medium < large)Ordinal encoding
Very many unique valuesFrequency or target encoding
Tree-based models with few categoriesOne-hot is fine, label encoding can also work

Key takeaway

One-hot encoding is a small step in data preparation, but it shows a bigger principle: how you represent your data decides what your model can learn. Turning text into numbers is easy. Turning it into numbers that don't lie is the actual skill.
