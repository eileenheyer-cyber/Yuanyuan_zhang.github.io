Naive Bayes Classifier: Understanding Probabilistic Machine Learning

How Bayes’ theorem turns probabilities into predictions.

How Can Probability Help Us Make Predictions?

An e-mail arrives containing the words free and prize. Is it spam?

You cannot be certain, but you can reason about it. Spam often contains “free”, and legitimate mail (ham) rarely does. A classifier can turn that kind of evidence into a number: how probable is spam, given what I see?

That is the idea behind Naive Bayes, a family of classifiers that estimates how common each class is, estimates how likely each feature value is within each class, and combines the two with Bayes’ theorem. It is simple, fast and a strong baseline for text. It also makes one assumption that is almost never exactly true. This post shows what that assumption is, why the method often works anyway, and where it breaks.

Understanding Bayes’ Theorem

Bayes’ theorem reverses a conditional probability. In classification, A is the class and B is the evidence we observed.

P(A | B) = P(B | A) × P(A)P(B)

The four components

TermNameIn spam filtering
P(spam | words)PosteriorWhat we want: probability of spam after seeing the words
P(words | spam)LikelihoodHow typical these words are in spam
P(spam)PriorHow common spam is before reading the e-mail
P(words)EvidenceHow common these words are overall; a normalizing constant

Intuition. The prior is your starting suspicion. The likelihood says how well the words fit “spam” compared with “ham”. The posterior is the updated suspicion.

A numeric example

Suppose 30% of mail is spam, 60% of spam contains “free” and 5% of ham contains “free”. These numbers are illustrative, not measured. For an e-mail containing “free”:

SpamHam
Prior0.300.70
P(“free” | class)0.600.05
Prior × likelihood0.1800.035

The evidence is P(“free”) = 0.180 + 0.035 = 0.215, so:

P(spam | “free”) = 0.180 / 0.215 ≈ 0.837

One word lifted the spam probability from 30% to about 84%. For the full derivation with a different example, see Bayes’ Theorem and Conditional Probability.

From Bayes’ Theorem to Naive Bayes

Choosing the most probable class

Let X = (x₁, …, xₙ) be the features (for example, words) and Y the class. By Bayes’ theorem, P(Y | X) is proportional to P(Y) × P(X | Y). The evidence P(X) is the same for every class, so for choosing a class we can drop it. This is maximum a posteriori (MAP) classification:

ŷ = argmaxy P(y) × P(x₁, …, xₙ | y)

The problem is the joint likelihood P(x₁, …, xₙ | y). It needs a probability for every combination of feature values, and with a 10,000-word vocabulary that cannot be estimated.

The “naive” assumption

Naive Bayes assumes the features are conditionally independent given the class, so the joint likelihood becomes a product of one small term per feature:

ŷ = argmaxy P(y) × ∏ P(xᵢ | y)

Now we only need one small distribution per feature per class. In practice we add logarithms instead of multiplying, to avoid numerical underflow.

Independence is not conditional independence

“Free” and “prize” are not independent overall: they appear together in spam. Naive Bayes only claims they are independent once we know the class. Even that is usually false, because spammers write “free prize” as a phrase. That is why the method is called naive.

Why it still works

Classification only needs the ranking of the classes to be right, not the exact probabilities. Correlated features can double-count evidence and push probabilities toward 0 or 1, yet the winning class is often still correct. A simple model with few parameters can also beat a flexible one that overfits on limited data (Domingos and Pazzani, 1997).

When correlation hurts. If many features are near-duplicates, the same signal is counted many times. Predictions become overconfident, and the ranking can flip when the duplicated signal points the wrong way.

An e-mail example

Add a second word to the earlier example, with P(“win” | spam) = 0.40 and P(“win” | ham) = 0.02 (illustrative numbers):

SpamHam
Prior0.300.70
× P(“free” | class)0.600.05
× P(“win” | class)0.400.02
Score0.07200.0007

Normalizing gives P(spam | “free”, “win”) = 0.0720 / 0.0727 ≈ 0.99.

The Variants of Naive Bayes

All variants share the same decision rule. They differ in how they model P(xᵢ | y).

Gaussian Naive Bayes

For continuous features. Within each class, each feature is modeled as a normal distribution with its own mean μ and variance σ²:

P(xᵢ | y) = 1√(2πσ²y,i) × exp( −(xᵢ − μy,i)²2σ²y,i )

import numpy as np
from sklearn.naive_bayes import GaussianNB

rng = np.random.default_rng(1)
# two numeric features per e-mail: number of links, share of capital letters
X_ham = np.column_stack([rng.poisson(1, 300), rng.beta(1, 15, 300)])
X_spam = np.column_stack([rng.poisson(4, 150), rng.beta(3, 14, 150)])
X_num = np.vstack([X_ham, X_spam])
y_num = np.r_[np.zeros(300), np.ones(150)]

gnb = GaussianNB().fit(X_num, y_num)
print("class means (rows: ham, spam):\n", gnb.theta_.round(2))
print("class variances:\n", gnb.var_.round(3))

Gaussian Naive Bayes can behave badly on strongly skewed features such as message length. Consider a log transform or scaling first. The parameter var_smoothing keeps tiny variances from producing zero densities.

Multinomial Naive Bayes

For counts, typically word counts in a document-term matrix: one row per document, one column per word. Each class gets a probability for every word, and an e-mail’s score depends on how often each word occurs.

import pandas as pd
from sklearn.feature_extraction.text import CountVectorizer

docs = ["free win free prize", "meeting project deadline", "free meeting project"]
vec = CountVectorizer()
dtm = vec.fit_transform(docs)                      # document-term matrix (sparse)
print(pd.DataFrame(dtm.toarray(), columns=vec.get_feature_names_out()))

# Multinomial NB uses these counts; Bernoulli NB uses presence/absence instead
binary = CountVectorizer(binary=True).fit_transform(docs)
print(binary.toarray())

Bernoulli Naive Bayes

For binary features: does the word occur, yes or no? Unlike the multinomial model, it also treats the absence of a word as evidence. In scikit-learn, pair BernoulliNB with CountVectorizer(binary=True), as in the second matrix above. Use Multinomial when frequency carries information and Bernoulli when only presence does, which is more typical for short texts.

Categorical Naive Bayes

For discrete categories such as sender type or attachment type. The model learns a category distribution per class. The input must be non-negative integers, so encode categories with OrdinalEncoder. A category that never appeared in training needs handling, for example through min_categories.

import pandas as pd
from sklearn.compose import make_column_transformer
from sklearn.naive_bayes import CategoricalNB
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OrdinalEncoder

meta = pd.DataFrame({
    "sender": ["unknown", "colleague", "unknown", "shop", "colleague", "unknown"],
    "attachment": ["none", "pdf", "exe", "none", "pdf", "zip"],
})
is_spam = [1, 0, 1, 0, 0, 1]

cat_nb = make_pipeline(OrdinalEncoder(), CategoricalNB(alpha=1.0))
cat_nb.fit(meta, is_spam)
print(cat_nb.predict_proba(pd.DataFrame({"sender": ["unknown"], "attachment": ["pdf"]})).round(3))

The Zero-Frequency Problem and Laplace Smoothing

Suppose a word never appears in the spam training examples. Its estimated probability in spam is 0. Because Naive Bayes multiplies probabilities, that one zero wipes out the whole product, however strong the other evidence is.

How smoothing works

Laplace (additive) smoothing adds a pseudo-count α to every word count:

P(wᵢ | y) = Ny,i + αNy + α × V

Ny,i is how often word i occurs in class y, Ny is the total number of word tokens in class y, and V is the vocabulary size. α = 1 is classic Laplace smoothing; other values are called Lidstone smoothing. Intuitively, you pretend to have seen every word α extra times in every class. Treat α as a hyperparameter and tune it with cross-validation.

Before and after

A tiny training set, counted by hand. Spam: “free win free”, “win free prize”, “free prize win”. Ham: “meeting project free”, “project deadline meeting”, “meeting schedule project”. The vocabulary has V = 7 words, and each class has 9 word tokens. Classify “free meeting” with equal priors:

No smoothingα = 1
P(“meeting” | spam)0 / 9 = 01 / 16
P(“free” | spam)4 / 95 / 16
P(“free” | ham)1 / 92 / 16
P(“meeting” | ham)3 / 94 / 16
P(spam | text)0.0000.385 (5/13)

Without smoothing, one unseen word makes spam impossible. With smoothing, ham is still favored, but spam keeps a realistic probability.

from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import Pipeline

docs = ["free win free", "win free prize", "free prize win",
        "meeting project free", "project deadline meeting", "meeting schedule project"]
labels = [1, 1, 1, 0, 0, 0]          # 1 = spam, 0 = ham

for a in [1e-10, 1.0]:
    p = Pipeline([("c", CountVectorizer()),
                  ("nb", MultinomialNB(alpha=a, force_alpha=True))]).fit(docs, labels)
    print("alpha =", a, p.predict_proba(["free meeting", "free win"]).round(3).tolist())
alpha = 1e-10 [[1.0, 0.0], [0.0, 1.0]]
alpha = 1.0 [[0.615, 0.385], [0.091, 0.909]]

The columns are P(ham) and P(spam). With a near-zero α the probabilities are extreme and brittle; with α = 1 they are moderate.

Practical Implementation: E-mail Spam Classification

The examples use simulated e-mails so that the post is fully reproducible. Replace the DataFrame with your own data and the rest stays the same. In the simulation, each e-mail contains five topical words and three neutral words, and 30% of the topical words come from the other class, so the task is not trivially easy.

  • 1. Load and inspect the data and check the class balance.
  • 2. Define the target: spam, 1 for spam and 0 for ham.
  • 3. Choose the features: the raw text. Vectorizing happens inside the pipeline.
  • 4. Split into train and test, before fitting anything.
  • 5. Vectorize with CountVectorizer to build the document-term matrix.
  • 6. Train MultinomialNB.
  • 7. Predict classes and probabilities on the test set.
  • 8. Evaluate with the confusion matrix, precision, recall, F1 and ROC-AUC.

Data, target and features (steps 1 to 3)

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import Pipeline
from sklearn.metrics import (classification_report, confusion_matrix,
                             roc_auc_score)


# Steps 1-3: load / inspect, target, features (simulated e-mails; replace with your own DataFrame)
rng = np.random.default_rng(7)
spam_words = ["free", "win", "prize", "gift", "pharmacy", "limited", "online", "claim"]
ham_words = ["meeting", "invoice", "deadline", "project", "receipt", "lunch", "schedule", "team"]
neutral = ["hello", "please", "today", "update", "thanks", "info", "you", "order"]

def make_email(is_spam):
    own, other = (spam_words, ham_words) if is_spam else (ham_words, spam_words)
    # each topical word comes from the other class 30% of the time (noise)
    topical = [rng.choice(other if rng.random() < 0.30 else own) for _ in range(5)]
    words = topical + list(rng.choice(neutral, 3))
    rng.shuffle(words)
    return " ".join(words)

n = 2000
y = (rng.random(n) < 0.30).astype(int)
df = pd.DataFrame({"text": [make_email(label) for label in y], "spam": y})
print(df.head(3))
print(df["spam"].value_counts(normalize=True))

# Steps 2-3: target and features
X, target = df["text"], df["spam"]

Split, vectorize and train (steps 4 to 6)

# 4. Split (stratified, before any fitting)
X_train, X_test, y_train, y_test = train_test_split(
    X, target, test_size=0.25, stratify=target, random_state=42)

# 5-6. Vectorize + train inside one Pipeline (vocabulary learned on train only)
model = Pipeline([
    ("counts", CountVectorizer()),
    ("nb", MultinomialNB(alpha=1.0)),
])
model.fit(X_train, y_train)

Why a Pipeline? CountVectorizer learns the vocabulary. If you fit it on all the data before splitting, words from the test set leak into the model. Inside a pipeline, fit sees only the training data, and the same object works unchanged in cross-validation. This is the same fit-on-train rule described in Feature Engineering.

Predict and evaluate (steps 7 and 8)

# 7. Predict
pred = model.predict(X_test)
proba = model.predict_proba(X_test)[:, 1]

# 8. Evaluate
print(confusion_matrix(y_test, pred))
print(classification_report(y_test, pred, digits=3))
print("ROC-AUC:", round(roc_auc_score(y_test, proba), 4))
# Which words push towards spam?
vec, nb = model.named_steps["counts"], model.named_steps["nb"]
log_ratio = pd.Series(nb.feature_log_prob_[1] - nb.feature_log_prob_[0],
                      index=vec.get_feature_names_out())
print(log_ratio.sort_values(ascending=False).head(5).round(2))
claim       0.99
win         0.95
free        0.87
pharmacy    0.86
limited     0.80

The last block shows what the model learned: the log-ratio of each word’s probability in spam versus ham. This is the interpretability advantage of Naive Bayes.

Why accuracy can mislead

Here 70% of the e-mails are ham, so a “model” that always answers ham scores 0.70 accuracy while catching no spam at all. Our 0.832 must be judged against that baseline, and precision and recall tell the real story. With only 5% spam, the always-ham baseline would reach 95%.

The two kinds of error also have different costs. A false positive (ham marked as spam) can bury an important message, so many filters favor precision. A false negative (spam reaches the inbox) is an annoyance or a security risk, and recall matters more when phishing is the worry. You can move the decision threshold on predict_proba to trade one against the other.

Predicted vs. calibrated probabilities

predict_proba returns the model’s scores. They only count as calibrated probabilities if, among e-mails scored around 0.7, about 70% really are spam. To check, bin the predictions and compare them with the actual spam rate:

cal = pd.DataFrame({"p": proba, "spam": y_test.to_numpy()})
cal["bin"] = pd.cut(cal["p"], [0, 0.1, 0.5, 0.9, 1.0], include_lowest=True)
print(cal.groupby("bin", observed=True)
         .agg(n=("spam", "size"), mean_predicted=("p", "mean"), actual_rate=("spam", "mean"))
         .round(3))

Do not generalize this result

The probabilities here are close to calibrated because the simulated words really are independent given the class, so the Naive Bayes assumption holds by construction. In real text, correlated words usually make Naive Bayes overconfident, with scores bunched near 0 and 1. Always run this check on your own data, and if you need trustworthy probabilities, wrap the model in CalibratedClassifierCV.

Advantages and Limitations

Advantages

  • Fast. Training is counting, and it scales to very large vocabularies.
  • Works with little data. It estimates few parameters.
  • Few hyperparameters. Mostly α.
  • Interpretable. Per-word log-ratios show what drives a prediction.
  • A strong text baseline. Easy to build before trying anything heavier.

Limitations

  • Independence is rarely true. Probabilities tend to be overconfident when features are correlated.
  • No interactions. It cannot learn that “not” changes the meaning of “free”.
  • Gaussian NB assumes bell-shaped features within each class.
  • Smoothing is mandatory to avoid zero probabilities.
  • Not always competitive. A tuned discriminative model can win with enough data, so compare against a baseline on every problem.

A common pattern is that Naive Bayes does well with little data, while discriminative models such as logistic regression can overtake it as the training set grows. This depends on the problem, so test both.

Key Takeaways

  • Naive Bayes picks the class with the highest P(Y) × ∏ P(xᵢ | Y).
  • The “naive” part is conditional independence of the features given the class.
  • Choose the variant to match the data: Gaussian, Multinomial, Bernoulli or Categorical.
  • Always smooth (α > 0) and tune α.
  • Keep vectorizing and modeling in one Pipeline.
  • Judge it with precision, recall, F1 and ROC-AUC, not accuracy alone, and treat its probabilities as scores until you have checked calibration.

Key takeaway

Naive Bayes shows that a prediction can be reasoning under uncertainty rather than a black-box verdict: start from a prior, weigh the evidence, update the belief. The independence assumption is false in most real data, yet the method is often a hard-to-beat baseline for text. Treat its probabilities as scores, check them before trusting them, and always compare it against a simple baseline.
