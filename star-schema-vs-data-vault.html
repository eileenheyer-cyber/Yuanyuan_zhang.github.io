Star Schema vs. Data Vault 2.0

Academic project report: comparing Star Schema and Data Vault 2.0 on a market-basket analysis built from receipt data.

Role

Data modeling, analysis, evaluation

Context

Project report, IU International University

Technology

SQL, Dimensional Modeling, Data Vault 2.0

Status

Completed

Starting point

The basis is a digital retail receipt with header- and line-item-level data. The goal was a market-basket analysis at the individual line-item level — the level at which it becomes visible which products occur together in one purchase. On this basis I developed both a Star Schema (per Kimball) and a Data Vault 2.0 model (per Linstedt) and compared them against each other.

Star Schema

  • Central fact table Fact_Sales_Item at line-item granularity
  • Three dimension tables: Dim_Product, Dim_Date, Dim_Store
  • The star-shaped structure makes the analytical axes immediately visible

Data Vault 2.0

Built from Hubs (business objects such as receipt, product, store), Links (relationships between them) and Satellites (descriptive, historized attributes) — with hash keys, load date and record source for traceability.

Result

For this use case — a single data source, direct market-basket analysis — the Star Schema proves more suitable: simpler, easier to understand, faster to use. Data Vault scores on flexibility, historization and extensibility, and would show its value primarily with multiple source systems and growing data landscapes.
